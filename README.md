# Singlite Single · 单机轻量版

一个面板直接管理安装它的 VPS：VLESS Reality、SS2022、用户管理、上传 + 下载配额，以及可选的 Mihomo / Clash Meta 订阅。节点保存后自动应用，默认导出 `vless://` / `ss://` 直接节点链接。独立的「订阅转换」还可以把其他机器手工搭建的节点转换为 Mihomo 订阅，后置机器无需安装面板。

本版使用真正的 **sing-box 1.14.3-singlite**，有授权用户的节点各自运行独立核心进程，由同一面板管理。使用 Python 标准库后端、SQLite 和原生网页，无需额外网页框架。只有一个安装脚本；安装完成后登录即可创建节点和用户。

项目地址：https://github.com/7665188-star/singlite

**部署流程：准备域名 → SSH 中复制两段命令 → 登录面板创建节点和用户。** 仓库已公开，下载源码无需 GitHub 账号、令牌或手动上传压缩包。

下面按全新 VPS、自带自动 HTTPS 编写；已有 Nginx / Caddy 的服务器使用第 6 节的已有反代方式。旧多 VPS 版不会自动迁移，请保留旧数据并在全新环境测试。

## 1. 准备 VPS 和域名

- Debian 12+ / Ubuntu 22.04+，正常运行 systemd，root / sudo 权限。
- 支持 amd64 / arm64。首次编译建议 2 GB 内存及至少 3 GB 空闲磁盘，临时构建约占 2 GB，完成后清理。每个实际运行的节点有一份 sing-box 内存开销；没有授权用户的节点不启动进程。
- 域名如 `panel.example.com`，A 记录指向这台 VPS。IPv6 确实可用时才添加 AAAA。
- 初次部署建议使用 DNS 直连解析。节点使用域名时需要直连 VPS；使用面板 CDN 时，请在面板设置将节点地址改为该 VPS 公网 IP。
- 首次构建需能访问 `go.dev`、GitHub / `codeload.github.com`、`proxy.golang.org` 和 `sum.golang.org`。

在厂商安全组和系统已有防火墙中放行：

| 用途 | 端口 |
| --- | --- |
| SSH 连接 | 你实际使用的 SSH TCP 端口 |
| 面板 HTTPS 和证书申请、续期 | TCP 80、443 |
| VLESS Reality 示例 | TCP 8443 |
| SS2022 示例 | TCP **及 UDP** 8388 |

8787 为面板本地后端。每个运行节点的统计接口由面板分配空闲的 127.0.0.1 端口，均不对公网开放，也无需在安全组放行。10085 保留兼容旧版；节点不能使用 80、443、8787、10085 或其他节点正在使用的内部统计端口。

## 2. 从 GitHub 下载并安装

用 FinalShell、Termius、Xshell 等 SSH 工具连接 VPS。以下命令均在 **VPS 的 SSH 终端**执行，使用 root；普通账号先执行 `sudo -i`。首次构建需要数分钟，建议使用下面的 tmux 会话，SSH 断开也可以继续安装。

**第一段：安装下载工具并进入 tmux。**

```bash
apt-get update && apt-get install -y ca-certificates git tmux &&
tmux new -s singlite
```

**第二段：进入 tmux 后，整段复制执行，下载源码并安装面板、核心和自动 HTTPS。**

```bash
git clone https://github.com/7665188-star/singlite.git /root/singlite &&
cd /root/singlite &&
bash install.sh --with-caddy
```

依次填写面板域名（例如 `panel.example.com`，不带 `https://`）、管理员用户名、管理员密码和确认密码。用户名默认 `admin`，支持 3–64 位字母、数字或 `_ . -`；密码支持 6–1024 位，输入不显示，建议使用较长的独立密码。

看到「Singlite 单机版安装完成」后，在浏览器打开 **https://你的面板域名**，使用刚设置的管理员账号登录。然后按第 3 节创建节点和用户即可。

源码保存在 `/root/singlite`；实际程序在 `/opt/singlite`，配置和数据在 `/etc/singlite`、`/var/lib/singlite`。仓库公开不会公开你在 VPS 上创建的用户和节点配置，不要将这些运行数据提交到 GitHub。

命令中的 `&&` 表示上一步成功才继续。出现错误时先处理提示，不要继续复制后续安装命令。若 `/root/singlite` 已存在，不要删除目录重装；已安装的面板按第 7 节升级，中断的安装按第 7 节恢复。

SSH 意外断开后，重新连接 VPS，执行以下命令回到原会话：

```bash
tmux attach -t singlite
```

若提示已有同名会话，也执行上面的命令进入；安装器仍在运行时等待它完成，不要启动第二个安装器。

若提示 TCP 80 / 443 已占用，且服务器上有需要保留的网站，按第 6 节使用已有反代。安装器会自行安装其余系统依赖，下载并校验核心源码、编译核心和配置服务，不需要手动安装 Python 框架、Node.js 或 Go。

首次 HTTPS 证书签发可能需要稍等。网页打不开时，先确认域名已解析到该 VPS，安全组和防火墙放行 TCP 80、443，再查看：

```bash
systemctl status singlite-panel singlite-web --no-pager -l
journalctl -u singlite-web -n 60 --no-pager
curl -fsS http://127.0.0.1:8787/api/health
```

健康检查返回 `"ok": true` 表示本机后端与核心统计已就绪；公网域名、证书和节点端口仍需实际访问确认。

## 3. 创建节点与用户

在「节点管理」点击「新建节点」：

| 协议 | 参数 | 放行端口示例 |
| --- | --- | --- |
| VLESS Reality | 名称、端口、SNI，默认 **www.amd.com** | 8443 / TCP |
| SS2022 | 名称、端口、AES-128 或 AES-256 | 8388 / TCP + UDP |

Reality 不需要为节点申请自己的 TLS 证书；SNI 目标需从 VPS 可访问并支持 TLS 1.3。凭据自动生成。保存后本机自动应用，无需额外发布步骤；若端口冲突，页面会提示并暂停核心，可在「运行日志」排查。

在「用户管理」创建用户：设置名称、额度、到期日期、重置周期和节点权限。默认授权全部节点，包括以后新增的节点；也可指定节点。没有授权用户的节点不会开放代理入站。

每人有独立 UUID 和 SS2022 用户密钥。用户修改自动生效；到期、超额、停用和权限变化只应用到包含该用户的节点。新建、删除其他节点不会重启正在使用的节点；删除当前连接的节点，或更改其端口、SNI、加密方式，仍会中断该节点的连接。名称和前置入口仅影响导出，不触发重启。

## VLESS Reality / SS2022 使用前置转发

创建或编辑 VLESS Reality、SS2022 节点时，有三个不同的地址 / 端口设置：

| 设置 | 填什么 | 用途 |
| --- | --- | --- |
| 本机监听端口 | 后置 VPS 上 sing-box 实际监听的端口，例如 8388 | 前置机把流量转发到这里，不要填前置机端口。 |
| 前置机 IP / 域名（可选） | 客户端能访问的转发入口，例如 203.0.113.10 | 导出的 vless://、ss:// 和 Mihomo 订阅使用此地址，只填写 IP 或域名，不含协议、路径、端口。支持 IPv4 / IPv6。 |
| 前置机端口（可选） | 前置机对外提供的端口，例如 18443 | 导出配置使用此端口；留空时沿用本机监听端口。 |

例如后置 VPS 是 `198.51.100.20`，sing-box 监听 `8388`，前置机是 `203.0.113.10:18443`，填写本机监听端口 `8388`、前置机地址 `203.0.113.10`、前置机端口 `18443`。

实际连接路径如下：

```text
客户端 → 203.0.113.10:18443 → 198.51.100.20:8388 → 目标网站
```

面板只修改导出配置的连接入口，不登录前置机、不创建转发规则、不修改后置节点的监听地址、监听端口、加密方式或密钥。VLESS 的 SNI、UUID、Reality 公钥和 short ID 也保持不变。前置机需提前配置透明 TCP 转发，SS2022 使用 UDP 时还需同时配置 UDP 转发，并放行对应安全组 / 防火墙端口。VLESS 的 UDP 通过其 TCP 连接承载。这里适用于透明转发原始节点流量；如果前置机需要另一套代理认证或协议封装，还需要客户端及前置服务支持相应连接方式。

不使用转发时，两个前置机字段都留空，地址继续采用「面板设置」中的本机公网地址。仅填写前置地址、前置端口留空也可，此时入口端口与本机监听端口相同。只填写前置端口而不填写地址会被拒绝，以免导出错误入口。

如果实际链路是「客户端 → 阿里云杭州 → 野草云 IX → 野草云 HK」，且两段均为透明 TCP / UDP 转发：Singlite 在 HK 管理后置 SS2022，本机监听端口填写 HK 的节点端口；前置地址填写杭州机器的公网 IP / 域名，前置端口填写杭州对外提供的入口端口。IX 的地址和端口只用于中继转发规则，不填成客户端入口。

已有节点可以直接编辑补填，保持原用户凭据和用量。更新入口后，直接链接需重新复制导入，订阅用户更新订阅即可；已有客户端保存的旧地址不会自动改变。清空前置地址和端口即可恢复直连，不影响其他节点。仅修改入口不会触发 sing-box 核心重载；订阅标题仍为 **Singlite · Proxy**，客户端不显示流量和到期信息。

## 4. 流量配额与重置

**已用流量 = 上传 + 下载**，在本机的全部授权节点合并累计。例如上传 2 GB、下载 8 GB，消耗 10 GB；1 GB = 1,000,000,000 字节。额度 0 表示不限量。

面板的节点页汇总、用户列表和个人订阅弹窗只显示**剩余流量**，统一使用 GB（1 GB = 10⁹ 字节），不显示已用量。剩余量按「总额度 − 上传 − 下载」计算，最低为 0；不足 0.01 GB 时明确提示，不限量用户显示「不限量」。汇总只包含限额用户。总额度仍可在编辑用户时修改。

**代理客户端的流量与到期信息已关闭**：订阅不发送 Subscription-Userinfo，不提供上传、下载、总额度或到期时间，也不把剩余量拼入名称。客户端的订阅标题统一为 **Singlite · Proxy**；响应头、订阅正文标题、下载文件名和面板网页标题使用同一名称，兼容不同客户端的取名方式。后台继续累计真实双向流量并执行额度、停用和到期限制；剩余量及有效期在面板查看。

**升级后请在代理客户端删除旧订阅，再复制面板订阅链接重新导入一次**，清除旧标题、流量和到期缓存。导入时保留自动名称；客户端已有的手填备注不会被服务端强制覆盖，如仍保留旧备注，请将其改为 **Singlite · Proxy**。

- 到期日期按北京时间当天 23:59:59 到期，留空长期有效。
- 可每月自动重置，或仅手动重置。每月重置按北京时间 00:00，不足指定日时按月末。
- 修改重置日不会立即清空；「重置流量额度」会同时清零上传与下载。
- 本机约每秒批量采样各节点，按节点区分统计游标，当前计数和累计用量在同一 SQLite 事务中提交。不同节点独立重启不会重复计费。正常重启不重置用量；周期重置后继续使用原采样游标，避免重复计费。
- 单个节点统计持续异常时只暂停该节点，恢复后自动开启。停止面板会停止它管理的全部节点，避免脱离配额管理。

配额停用有采样和重启延迟，不是逐字节硬上限。意外断电可能丢失最后一次持久化采样后的少量流量。这里统计代理用户字节，厂商还可能计算物理收发、协议开销、系统更新和其他服务，账单可能不同。

## 5. 默认直接链接，可选订阅

节点或用户行点击「节点链接」，选择使用哪位用户的身份，复制 `vless://` / `ss://`，导入支持相应协议的客户端。流量计入所选用户。初次保存节点后，等核心显示运行正常再测试。

导出的节点名称与面板填写的名称完全一致，例如 `vmiss`，不会附加编号。订阅标题统一为 `Singlite · Proxy`，不附加流量或到期信息；订阅内的节点本身仍保持 `vmiss` 等面板名称。已有订阅请删除后重新导入，清除旧标题和信息缓存。使用 Mihomo 订阅时，授权节点请使用不同名称，并避开 DIRECT、节点选择、自动选择等客户端保留名称。

Mihomo / Clash Meta 用户可单独点击「订阅」，添加个人远程配置。它汇总该用户有权限的本机节点，并带选择和测速分组。传统旧版 Clash 可能不支持 Reality / SS2022；当前订阅为 Mihomo YAML，不是所有客户端通用格式，其他客户端优先使用直接链接。

订阅地址持有者可以获取该用户的配置，请保密。重置订阅地址会让旧地址不能更新；已导入的节点凭据仍有效。要停止用户连接，请停用或删除用户；超额和到期也会在本机执行停用，订阅返回 403。

## 手工节点订阅转换

适用于 HK 已有其他网站、只想手工搭建代理节点的情况。Singlite 可以部署在另一台 VPS；HK 只运行自己的节点，沿用已有网站服务，Aliyun / IX 转发也继续使用原有配置。

1. 在 HK 手工搭建 SS2022 或 VLESS TCP Reality，取得完整的 `ss://` 或 `vless://` 节点链接。
2. 如果使用「杭州 → IX → HK」转发，先确认链接中的连接 IP / 域名和端口是杭州的对外入口。SS 密钥及 VLESS 的 UUID、SNI、公钥、short ID 继续使用 HK 节点的原值。
3. 登录 Singlite，侧栏进入「订阅转换」，新建记录，填写名称并粘贴链接。多个节点每行一个，名称应不同。也支持粘贴这些节点链接组成的 Base64 文本。
4. 保存后记录出现在独立列表。复制订阅地址，在支持相应协议的 Mihomo 客户端中添加远程配置；也可以下载 YAML。
5. 编辑同一条记录后，订阅地址保持不变，客户端更新订阅即可获取修改。删除记录后，其订阅地址返回 404；已导入的节点凭据仍可使用，需要停止连接时请在 HK 更改密钥或停用节点。

转换工具只输出 Mihomo YAML，不负责部署节点、生成转发规则、获取外部节点实时流量或执行其配额。记录不出现在「节点管理」「用户管理」，不会写入本机 sing-box 配置，也不会触发核心重启。面板停止本机核心时，独立转换订阅仍可获取；面板网页服务本身需要持续运行才能提供订阅更新。

目前支持 SS2022 AES-128 / AES-256 的单密钥、服务端密钥加用户密钥链接，以及 TCP / Reality 的 VLESS（空 flow 或 Vision，保留指纹及 ALPN）。支持域名、IPv4、IPv6 和编码后的中文名称。不支持远程订阅 URL 拉取、WS / gRPC、SS 插件、其他协议及非空 spx；遇到未支持的参数会明确报错，避免丢失配置。每组输入最多 256 KiB。

转换在面板自己的后端完成，不调用第三方转换站点。只有登录管理员可以管理记录；公开订阅地址持有者可以获取节点凭据，请保密。转换订阅标题同样固定为 **Singlite · Proxy**，不发送客户端流量和到期信息。节点本身继续使用导入链接中的名称。

## 6. 已有 Nginx / HTTPS 网站

先确认占用：

```bash
ss -ltnp '( sport = :80 or sport = :443 or sport = :8787 or sport = :10085 )'
```

已有网站需要保留时，先按第 2 节第一段准备工具并进入 tmux，再执行以下命令。只需选择这一种安装方式，不要先执行 `--with-caddy`：

```bash
git clone https://github.com/7665188-star/singlite.git /root/singlite &&
cd /root/singlite &&
bash install.sh --existing-proxy
```

如果第 2 节已经成功下载源码，只执行 `cd /root/singlite && bash install.sh --existing-proxy`。此模式仍然安装本机面板和 sing-box，使用已有的 HTTPS 反代；需要按下面的示例配置现有网站。已安装的面板不要用全新安装参数覆盖，按第 7 节处理。

为面板域名单独配置 Nginx HTTPS server 块，在其中添加：

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_cache off;
}
```

域名、443 监听和证书使用你自己的配置。已有 Caddy 可使用：

```caddyfile
panel.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

保留 Host 和 X-Forwarded-Proto；不要缓存 `/api/`、`/sub/`、`/convert/`，不要在订阅路径前额外添加网页登录验证。生产 Cookie 强制 Secure，必须通过 HTTPS 登录。

## 7. 升级、中断恢复与密码重置

升级前请暂时关闭经过本机节点的 TUN / 代理，使用直连 SSH；升级需要短暂停止全部本机节点，运行中的 SSH 如果经过它们也会断开。建议在 tmux 内升级，等待显示安装完成并确认节点恢复后再开启 TUN。

**以后升级：** 在 tmux 中执行下面一段，下载 GitHub 最新代码，再升级已安装的面板。安装器会在升级前备份并保留节点、用户和用量，沿用已有 HTTPS 模式。

```bash
cd /root/singlite &&
git pull --ff-only origin main &&
bash install.sh --upgrade
```

仅 `git pull` 不会更新正在运行的面板，必须执行后面的安装器。更新失败时后续升级不会执行。若提示本地代码被修改或历史分叉，先保留自己的修改再处理，不要使用强制重置。原来通过压缩包安装的 `/root/singlite-single` 不是 Git 仓库时，先按第 2 节的 `git clone` 命令下载到 `/root/singlite`，再执行 `cd /root/singlite && bash install.sh --upgrade`，不需要卸载已有面板。

**安装中断：** SSH 断开后先执行 `tmux attach -t singlite` 回到原会话；安装器仍在运行时等待它完成。确认进程已结束后，进入源码目录：

```bash
cd /root/singlite
```

- 尚未创建单机版安装目录：重新运行原安装命令。
- 已创建单机版配置：执行 `bash install.sh --resume`，保留域名、管理员和数据继续。
- 中断时使用已有反代：执行 `bash install.sh --resume-existing-proxy`。
- 已完成安装、需要更新版本：使用上面的 GitHub 升级命令。

安装器会阻止重复并发安装。构建失败发生在写入安装文件之前；继续安装和升级会为已有程序、配置和数据创建权限 600 的备份。不要为解除提示直接删除 `/var/lib/singlite`。

忘记管理员密码，在源码目录执行：

```bash
cd /root/singlite &&
python3 scripts/reset-admin.py
```

交互设置新的用户名和 6–1024 位密码；工具备份原摘要并重启面板，旧登录会话失效。

## 8. 验收、日志和备份

先确认面板能通过 HTTPS 登录、本机核心运行正常。再用用户的直接节点链接实际连接，等待几秒检查上传与下载增加。可给测试用户设置小额度，验证超额停用和重置恢复。

```bash
journalctl -u singlite-panel -n 60 --no-pager
journalctl -u 'singlite-node@*' -n 80 --no-pager
/opt/singlite/bin/sing-box version
systemctl list-units 'singlite-node@*' --no-pager
ss -lntup
```

没有代理连接时统计可能为空，这是正常现象。面板能打开不等于节点 TCP / UDP 已经放行；Reality 还需确认 SNI 可达。

程序在 `/opt/singlite`，环境配置在 `/etc/singlite`，管理员、SQLite 用量账本和各节点配置在 `/var/lib/singlite`，节点配置位于 `nodes/<节点ID>.json`。服务为 `singlite-panel`、`singlite-node@<节点ID>.service`，自带 HTTPS 时另有 `singlite-web`。节点由面板按授权启动，不要单独 enable 节点服务。旧单核心服务在升级时停用，原节点密钥、端口、用户、用量和订阅转换记录均保留，统计游标自动迁移。首次切换版本会统一重启一次；之后日常增删不影响其他节点。

备份应复制完整数据目录，不能只复制 SQLite 主文件：

```bash
umask 077
systemctl stop singlite-panel
tar -czf /root/singlite-single-backup.tar.gz -C / opt/singlite etc/singlite var/lib/singlite
systemctl start singlite-panel
```

备份含密钥与订阅地址，请保密。不要在不同 VPS 共用同一份运行中的用量数据库。

源码带单机数据、认证、流量和安装恢复测试：`python3 -m unittest discover -s tests -v`。本地回环验证不能替代你的 VPS 的 systemd、DNS、公网证书和安全组验收。

协议范围参考 [singbox-deploy](https://github.com/caigouzi121380/singbox-deploy)，核心采用 [sing-box v1.14.3](https://github.com/SagerNet/sing-box/tree/v1.14.3)，保留其许可证。

## 功能与使用限制

Singlite 是这台 VPS 的管理员后台。代理用户使用各自的节点凭据连接，不需要登录网页。安装一次即可在面板完成节点、用户和流量管理。

| 功能 | 具体行为 |
| --- | --- |
| 单机管理 | 一个面板直接管理所在 VPS，有授权用户的节点分别运行 sing-box；新增、删除、修改某节点只应用到该节点，无需接入令牌或额外 Agent。 |
| VLESS Reality | TCP + Vision，自动生成 Reality 密钥和 short ID；默认 SNI 为 `www.amd.com`，可自行修改。Reality 节点无需申请自己的 TLS 证书。 |
| SS2022 | 支持 2022-blake3-aes-128-gcm、2022-blake3-aes-256-gcm，支持 TCP 与 UDP，每位用户使用独立身份密钥。 |
| 节点操作 | 新建、编辑名称和端口、修改 SNI / SS 加密方式、启用、停用、删除、搜索和按协议筛选。已有节点更换协议需新建。 |
| 前置转发入口 | VLESS Reality 和 SS2022 都可单独填写前置机 IP / 域名、连接端口。节点链接和订阅使用前置入口，本机继续监听原端口；留空保持直连。 |
| 用户管理 | 设置名称、备注、启停、额度、有效期和节点权限；VLESS UUID 与 SS2022 用户密钥自动生成，用户之间相互独立。 |
| 节点权限 | 可授权指定节点，或选择全部节点。选择全部时，以后新增的节点也自动授权；删除节点会清理对应权限。 |
| 双向配额 | 按节点、用户和进程代次分别保存统计游标，同一用户在全部授权节点的上传与下载合并扣减一份额度。1 GB = 1,000,000,000 字节，0 代表不限量；面板统一显示剩余 GB。 |
| 额度周期 | 支持仅手动重置或每月自动重置；月度重置按北京时间 00:00 执行，重置日为 29–31 日且该月不足时按月末。重置不会让旧核心计数再次计费。 |
| 用户有效期 | 指定日期按北京时间当天 23:59:59 到期；留空为长期有效。停用、到期或用尽额度后，本机核心会移除相应用户授权。 |
| 直接节点链接 | 默认复制 vless:// 或 ss://，可选择使用哪位用户的身份。导出的节点名称与面板名称一致，例如 vmiss。 |
| 可选订阅 | 导出 Mihomo / Clash Meta YAML，包含授权节点、手动选择和自动测速分组。订阅标题固定为 Singlite · Proxy，代理软件不再接收流量或到期信息。 |
| 独立订阅转换 | 粘贴其他机器的 VLESS TCP Reality / SS2022 链接，生成稳定的 Mihomo 订阅地址；转换记录单独保存，支持查看、编辑和删除，不加入本机节点、用户或流量账本。 |
| 订阅地址重置 | 可更换个人订阅地址，旧地址随即无法更新。此操作不更换节点 UUID / 密钥；要撤销连接权限，应停用或删除用户。 |
| 核心与日志 | 查看核心版本、各节点运行与统计状态、CPU / 内存；支持手动暂停、启动、重启全部节点，以及查看最近 100 行节点日志。展示日志时隐藏当前凭据和节点链接。 |
| 管理员登录 | 一个管理员账号；密码 6–1024 位，支持 6 位数字，以加盐 scrypt 摘要保存。登录会话最长 12 小时，提供登录频率限制和请求来源 / CSRF 校验。 |
| HTTPS 部署 | 可使用自带 Caddy 自动申请和续期证书，或接入已有 HTTPS 反代。支持安装中断后继续、单机版升级与升级前备份。 |
| 数据与依赖 | 后端仅使用 Python 标准库和 SQLite，网页无需 Node.js 运行时。程序、配置和账本全部保存在本机；首次编译的临时工具链及模块缓存完成后清理。 |

当前最多允许 128 个本机节点、512 个代理用户，以及 64 组转换记录、每组最多 128 个手工节点。这是数据数量限制，不代表对任意 VPS 配置的并发性能承诺。

用量约每秒在后台批量采样，页面约每 5 秒刷新；订阅弹窗读取最新用户快照。普通保存操作不等待统计命令或核心重启，状态由后台自动应用。新建、删除、修改某个节点只影响该节点；其他节点的连接保持。修改用户凭据、权限、停用、超额或到期，会重新应用包含该用户的相关节点，可能中断这些节点上的其他用户。额度控制有采样和节点重启延迟，可能少量超用；意外断电仍可能损失最后一次持久化之后的少量数据。

这里的双向用量是代理用户字节。厂商账单还可能包含协议开销、系统更新、其他服务及物理网卡流量，无法保证与厂商账单逐字节一致。某节点统计持续不可用时，仅暂停该节点的代理入站，统计恢复后自动启用；其他正常节点继续运行。停止面板会停止它管理的全部节点。

节点实际需要在 VPS 安全组与防火墙中放行；面板不会自动改动已有防火墙或其他网站。Mihomo 订阅要求客户端支持 Reality / SS2022，传统旧版 Clash 的兼容性取决于其内核；其他客户端可使用直接节点链接。
